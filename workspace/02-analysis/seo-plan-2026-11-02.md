## 1. Archetype (5.1): Multi-location storefront
Two real, staffed offices (Elmhurst, Hicksville), addresses shown. Playbook: one GBP per location, one location page per GBP, shared service pages, schema node per location, run the grid and the feasibility gate per location. Never one plan "for all locations".

## 2. What the built site exposes today (dist/, checked 2026-11-02)
- Every page `noindex, nofollow` + robots.txt `Disallow: /`: correct for a demo. Note (13.11 item 2): robots.txt Disallow does NOT stop indexing, `noindex` does; both come off at launch together.
- No canonical, sitemap, Open Graph or JSON-LD. Titles unique; descriptions 40-70 characters and generic (target 150-160, titles 50-60, 13.11 item 5).
- Raw HTML is real content (static build): passes 13.11 item 1.
- Services exist only as a section on Home. No category pages, no service pages, no About page.
- Both location pages and both doctor pages exist (good: they are the GBP landing pages and the practitioner/Person pages).

## 3. The problem
Core 30 (13.8): the site must say what the Google profile says, in the same shape. Home is the landing page for ONE profile; each GBP category gets a page; each GBP service gets a page; About carries the E-E-A-T load. Today all ten services compete inside Home, and the playbook's own test case (narrow sites ranking "a couple of times but not consistently" until restructured to the full structure, DEEP02 K0097) is this situation.

URL rule (13.11 item 3): one pattern, service before location, no location repeated, 2-3 levels. Shared service pages (5.1) name both offices with each office's own details; this is NOT a city-swap (C.3), because there is one page per service, not one per town.

## 5. Decisions the client/owner must make (cannot be guessed)
1. Which office is the main GBP landing page that Home represents (13.8: Home is the landing page for ONE profile only; the other office's profile points to its own location page). Trade-off (K0232): pointing a profile at Home helps that profile rank and makes Home hard to rank for non-local keywords.
2. URL pattern: nested by category (recommended, above) or flat /services/...
3. Whether each doctor's text can be reviewed and signed (needed for every service page and the E-E-A-T line "reviewed by").

## 7. Flags against what we built (honest)
- Hidden content ranks lower (13.11.9): the FAQ accordion and the Services filter tabs. Keep the 10 service cards and the answers present in the HTML (they are), and give each service its own visible page.
- Animation (13.8, DEEP02 K0118: one coach, home-service sites, grade C): a static hero beat animated heroes and carousels, and animation slows load. We have a 1.2 s splash and live three.js on wide desktop. Measure field LCP/INP after launch before deciding; it is a conversion/speed risk, not proven for this site.
- Medical is YMYL: playbook 4.7/K0886 says to show SERP evidence and not promise results. No ranking promise anywhere (U18.18). Health claims on service pages need provider review (medical-wellness.5).
- Not needed: `BreadcrumbList` (only above 50-100 pages), `hreflang` (no Spanish version on the domain; "Language help" is only a line), a sitemap as an indexing fix.

## 8. Blocked on the client (cannot be faked)
Real domain, addresses, phones, hours, which office is the main profile, doctor credentials, doctor-reviewed service text, Google Business Profile ownership, whether booking/portal exist.
