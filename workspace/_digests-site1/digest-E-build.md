## 0. One-paragraph picture

Site1 is a config-driven Astro 7 + Tailwind 4 static site with exactly one server piece: a Cloudflare Worker (`worker/`) serving `/api/lead` backed by D1. All business facts live in one YAML (`business.yaml`), validated by a Zod schema. Pages, JSON-LD, footer NAP, theme colors and Worker env vars are all derived from it. A "fact rule" says: if it is not in `business.yaml`, it is not on the site; null/empty means the block renders nothing. A pile of build guards (`scripts/lib/guards-*.ts`) scan the built `dist/` HTML and fail the build for placeholders, unsupported claims, NAP drift, bad schema, bad links, bad headers, secrets in `wrangler.jsonc`, etc. The Owner (not the AI) deploys. The six-file `gbp-site-kit` is the human-process spine (intake -> GBP audit/SSOT -> scope/keywords -> content -> tech spec -> launch QA) and `business.yaml` is the machine form of the kit's file-02 SSOT.

Directory map: `site-template/` (reference template, fictional "Example Roofing", `is_sample: true`), `demos/kiln-and-coil/` (fictional Queens HVAC demo built from the template; far more elaborate), `design-lab/` (3 roofing home-page design directions A/B/C sharing template node_modules), `gbp-site-kit/` (6 md), `playbook/` (Lead-Site Playbook v1.1 + Universal playbook U00-U24, overlays incl. `medical-wellness`, `design-craft` anti-slop skill), `vault/wiki` (decisions, red lines), `docs/superpowers` (plans/logs).

## 1. Architecture of the template (`site-template/`)

### 1.1 Stack and versions
- Astro `^7.4.2` (pinned in lock as 7.4.2), Tailwind `^4.3.3` via `@tailwindcss/vite`, `output: 'static'`, `trailingSlash: 'always'`, `build.format: 'directory'`, `@astrojs/sitemap` (filters out `/design-system/`, `/thank-you/`, `/404/`).
- Zod `^4.6.7`, `yaml ^2.9.1`, `node-html-parser` (guards), vitest `^5.0.5` (+ v8 coverage), Playwright `^1.64.1` + `@axe-core/playwright`, `tsx`, `wrangler ^4.152`, `jsonc-parser`, `typescript ^6.0.3`.
- Fonts: self-hosted `@fontsource-variable/*` (template: Bricolage Grotesque + Instrument Sans). A guard fails any Google Fonts link.
- **Node: `engines: >=22.23.4`; docs say use Node 24 LTS.** On the original machine Node 26 (Current) was installed and Node 24.22.1 lived at `~/.local/share/node/node-v24.22.1-linux-x64/bin` (prepend to PATH). The current shell here reports `node v26.11.1`; the Node 24 binary dir exists under `/home/filwel/.local/share/node/`. Use Node 24 for the new repo.
- npm 11 warns esbuild/workerd install scripts are not approved; harmless per memory notes.

### 1.2 Data flow: `business.yaml` -> pages
1. `astro.config.mjs` reads `process.env.BUSINESS_FILE ?? 'business.yaml'` directly with `yaml.parse` and sets `site: record.website.canonical`.
2. `src/lib/business.ts` loads and validates the same file through `parseBusiness` (`src/lib/business.schema.ts`, 224 lines of Zod). `getBusiness()` is called in every layout/page/component. Invalid record = build error with the Zod path.
3. `src/lib/site.ts` holds the pure derivations: `offeredServices(b)` (only `offered_confirmed: true`, sorted by `revenue_rank`), `areasWithProof(b)` (area page exists only if `proof[]` non-empty), `pairContent()` (record item without a `src/content/<dir>/<slug>.md` file **fails the build** naming the missing file; content file without record item is ignored with a warning), `supportedReasons()`, `callInvite()` ("call and speak to a person" only if `conversion.answered_by_person`), `verifiedInsurance()` (insurance text only if `insurance_certificate_seen`), `formAvailable()` (form only if a Turnstile sitekey is set AND a service exists), `serviceCallFeeLine()`, `limit160()`, `pageTitle()`, `h1For()` ("<subject> in <place>").
4. `src/lib/claims.ts`: `keyPresent(record, "trust.licenses[].number")` mechanism. Copy that makes a claim is gated by `requires:` in content front matter (`why_us[].requires`).
5. Content collections (`src/content.config.ts`, glob loaders over `src/content/*`), Zod-schemas: `services` (summary, signs, process[{title,text}], related, faq), `areas` (summary, neighborhoods, landmarks), `faq` (question, services[], `home` bool; body rendered as **plain-text paragraphs**, no Markdown/HTML), `pages` (title, description<=160, subline, `why_us[{text,requires}]`; ids: home, about, privacy, terms, accessibility).
6. Pages in `src/pages/`: `index`, `about`, `contact`, `privacy`, `terms`, `accessibility`, `thank-you`, `404`, `design-system`, `robots.txt.ts`, plus dynamic service/area routes in the demo (`services/[slug]`, `areas/`). Pages are generated *from the record*, so removing a service from the YAML removes its page and every link to it.
7. `Layout.astro` takes `title, description, path, noindex, jsonLd[]`; emits canonical from `website.canonical`, OG/Twitter, inline theme `<style>` from `themeCss(b)`, JSON-LD via `serializeJsonLd` (escapes `< > & U+2028/9`), GA4 snippet only if `analytics.ga4_id`, skip link, Header, `<main id="main">`, Footer, StickyCallBar, delegated phone-click tracking.
8. `src/lib/jsonld.ts`: `buildBusinessNode` (@type chosen from `gbp.categories.primary` via a small map: roofing contractor -> RoofingContractor, hvac contractor -> HVACBusiness, plumber -> Plumber, general contractor -> GeneralContractor, else `LocalBusiness`), `buildServiceNode`, `buildAreaServiceNode`. SAB businesses never emit `address`/`geo`; no `aggregateRating`/`review` ever; GeoCircle only if `schema.allow_geocircle`. `@id` = `<canonical>/#business`.

### 1.3 `business.yaml` top-level shape (the record)
`version, status(draft|in-review|approved|locked), is_sample, template_version, identity{legal_name, display_name, business_model(storefront|sab|hybrid), primary_place, founded_year, ownership, languages}, contact{phone{e164 "+1XXXXXXXXXX", display}, tracking_phone{e164}, email_public, address{publish,street,unit,city,region,postal_code,geo}, hours{mon..sun "HH:MM-HH:MM"|null, emergency}, timezone}, website{canonical https}, gbp{maps_url, place_id, categories{primary, additional[]}}, services[{slug,name,category,gbp_service,offered_confirmed,revenue_rank,emergency,price_publish,price_range}], service_areas[{name,slug,proof[]}], offers{free_estimate,same_day,service_call_fee}, trust{reviews_summary, reviews[{text,author,platform,url,date,permission}], licenses[{type,number,issuer,registry_url,expires}], insurance, insurance_certificate_seen, team[{name,role,photo,consent}]}, conversion{primary_cta(call|form), form_destinations[], after_hours, answered_by_person, spam_control[], sms_consent_implemented}, analytics{ga4_id "G-XXXX", utm_on_listing_link}, brand{tokens{primary,secondary,accent,bg,surface,text,muted,on_accent}, tokens_dark, fonts{heading,body}}, claims{forbidden[], allowed_if_key_present{}, allow_phrases[]}, schema{allow_geocircle, geocircle}, provenance{}`.
Cross-field rules (superRefine): SAB must not publish address; non-SAB publishing needs street+city+region+postal_code; `insurance_certificate_seen` needs `insurance` text; `allow_geocircle` needs a geocircle. URLs must be https; hex tokens `#rrggbb`; font names letters/digits/spaces only (injection guard).

### 1.4 Components (`src/components/`), all record-driven; "empty = render nothing"
AreaList, CallButton (placement via `data-placement`; >=48px), CTABand, FAQ, Footer, Header, JsonLd, LeadForm, LicenseBlock, PersonCard, ProcessSteps, ReviewsEmbed, SectionHeading, ServiceGrid, StickyCallBar, TrustBar. `/design-system` page lists every component (name + path) and tokens; rule: check it before building UI, register new components there. The demo adds many more (Logo, ProofStrip, PriceClarity, CallSteps, HeatPumpFitCheck, TriageDoors, ThermostatDial, ExplodedView, HouseHero etc.), most trade-specific.

### 1.5 Tokens / theme
`src/styles/theme.css` has `@theme` defaults (`--color-primary/secondary/accent/bg/surface/text/muted/on-accent`, `--font-heading/body`). `src/lib/theme.ts` (`themeCss(b)`) turns `brand.tokens` (+ optional `tokens_dark` under `prefers-color-scheme: dark`) into an inline `:root` override. Utilities: `bg-primary`, `text-muted`... Rules: no hex or font names in components; one accent color for CTAs only; body contrast >= 4.5:1; call buttons >= 48px; no carousel/autoplay; reduced-motion respected. Demo extended with `panel`/`on_panel` tokens (inverse blocks) because a first dark mode left Footer/CTA unreadable. Note: Tailwind `@theme static` is wrong for per-business palettes (vault note).

### 1.6 Worker + lead pipeline (`worker/`, 11 files, ~1000 lines)
- `wrangler.jsonc`: `main: worker/index.ts`, `compatibility_date 2026-10-01`, `assets {directory ./dist, binding ASSETS, run_worker_first ["/api/*"]}`, D1 binding `DB` (database `leads`, `migrations_dir worker/migrations`; `database_id` is `REPLACE_WITH_D1_ID`), cron `*/15 * * * *`, `vars`: `SITE_ORIGIN, ALLOWED_SERVICES, EMERGENCY_SERVICES, FROM_EMAIL, ALERT_EMAIL_TO, OWNER_ALERT_TO` (optional `ACK_EMAIL="on"`).
- **Secrets (names only; set with `wrangler secret put`, never in the file):** `TURNSTILE_SECRET, SYNTHETIC_SECRET, IP_SALT, EMAIL_API_KEY, N8N_URL, N8N_SECRET`. A missing `EMAIL_API_KEY/FROM_EMAIL/ALERT_EMAIL_TO` is NOT caught at deploy; only the daily synthetic test + dead-man check catches it.
- Browser: `LeadForm.astro` posts JSON to `/api/lead`. No `PUBLIC_TURNSTILE_SITEKEY` at build time = form not rendered, page shows phone instead (fails closed). Fields: name, phone, service (dropdown from record), zip, email (optional), message (optional, <=1000 chars), honeypot `hp_site_url`, Turnstile token.
- Server guard order: method, Origin, content type, 16 KB cap, JSON, IP salt, synthetic signature, rate limit (5/min/client, counts rejects; IPv6 on /64), honeypot (stores `spam` row, shows success), field validation (before Turnstile since tokens are single-use), Turnstile, dedupe by phone within 10 min (same service/ZIP/message = repeat -> returns first id; differing = new lead flagged `repeat-phone`), store in D1, then background alert (email, `worker/email.ts` Resend-style API; provider is an open decision) + n8n sync. Success is returned only after the row is stored.
- Cron `scheduled.ts`: retries undelivered alerts (from 5 min to 48 h), tells Owner over two independent channels (email + n8n webhook `delivery_failure`), reminds every 6 h, re-copies leads to n8n (20 tries), purges attempts after 1 day and spam after 30 days. Exact-ish rate limit is not atomic in D1; a Cloudflare edge rate rule on `/api/lead` is required at launch.
- Migrations (not hand-edited DB): `wrangler d1 migrations apply leads --remote` (Owner runs). `worker/schema.sql` = current shape; `tests/d1-sqlite.test.ts` proves equality with migrations (the demo has `worker/migrations/0001_init.sql`, `0002_delivery_and_attempts.sql`; the template has no `migrations/` folder in the tree listing, so create it/copy from the demo when scaffolding; verify before first migrate).
- Logging is a fixed, secret-free line (`logEvent`); never request bodies/addresses.
- n8n only called if `N8N_URL` is https and `N8N_SECRET` set, no redirects, 8 s timeout; payload has `name_safe`/`message_safe` (leading apostrophe against spreadsheet formulas).

### 1.7 Security headers (`public/_headers`)
nosniff, `Referrer-Policy: strict-origin-when-cross-origin`, `X-Frame-Options: DENY`, `Permissions-Policy` (geo/mic/camera off), HSTS max-age 15552000, and a **Content-Security-Policy-Report-Only** (script-src self + unsafe-inline + challenges.cloudflare.com + googletagmanager; frame-src Turnstile; connect/img for GA). Guard `checkHeadersFile` requires these headers, rejects empty values, rejects `X-Robots-Tag: noindex` under `/*`, requires CSP directives and flags weak script sources in strict mode.

### 1.8 Guards that fail builds (`scripts/check-all.ts` -> `scripts/lib/run.ts`)
`check-all.ts` walks `dist/`, parses every HTML page, then `runGuards` returns violations (exit 1) and warnings. `MIN_PAGES=5`, required pages `/` and `/contact/`. Guards, in order:
- **pages**: completeness (>=5 pages, `/` and `/contact/`).
- **sample**: `is_sample: true` with `SITE_ENV` not development/test = fail. (This is why `check:prod` fails on the template.)
- **placeholders**: lorem / `{{` / SAMPLE / TODO-style text in page text and attributes (strict envs fail).
- **claims**: forbidden phrases from `claims.forbidden` (24/7 and many spellings, "licensed", "insured", "best", "fastest", "family-owned", "decades"...) with look-alike character folding (dashes, zero-width, odd spaces) and `allowed_if_key_present` mapping (e.g. "licensed" allowed only if `trust.licenses[].number` exists).
- **nap**: every phone string must be the record's display or E.164 form; `tel:` links must equal record E.164; footer must contain the display name; no street address on SAB sites.
- **license**: expiry parsing (YYYY-MM-DD), expired = fail ("remove the claim and the number the same day"), no-expiry = warning (fail in strict).
- **ctas**: forms need a real action, inputs need `name`, no `href="#"` without `data-action`, anchors must exist, `mailto:` non-empty, `tel:` must match `^tel:\+1\d{10}$`.
- **scripts** (guards-html): only allow-listed external script hosts and template-emitted inline scripts; no inline `on*=` handlers, `srcdoc`, `javascript:`/`data:` URLs, meta refresh, `<base href>`.
- **links**: every internal href/src must resolve to a built page/file.
- **schema**: JSON-LD parses; exactly one business node; business schema only on `/` and `/contact/`; telephone/name equal record; `areaServed` places must be record areas; no `aggregateRating`/`review`; no `address/geo` for SAB; `geoRadius` numeric <= 32000 m; Service nodes need `provider`.
- **images**: `alt` present (empty alt only if decorative), width+height present, hero not lazy and `fetchpriority="high"`; byte budgets (hero <=150 KB, others <=100 KB).
- **seo**: title present, <=70 chars, unique; exactly one h1; description present and <=160; `html lang`; canonical absolute, same origin, equals page's own URL; noindex expectations (design-system/thank-you/404 noindex, everything else indexable); no Google Fonts.
- **security**: `_headers` rules above.
- **deploy** (`scripts/lib/wrangler.ts`): `wrangler.jsonc` parses (JSONC); `SITE_ORIGIN/ALLOWED_SERVICES/EMERGENCY_SERVICES` equal record (fix with `npm run sync:config`); `main`, cron, D1 `DB` binding exist; no key named like a secret (`SECRET|TOKEN|KEY|PASS|SALT|WEBHOOK|N8N_URL`, except `PUBLIC_*`) or secret-looking value (`re_...`, `0x4AAAA`, `sk_`, Slack/Discord webhooks) in the file; in strict envs, no `REPLACE_WITH` or `example.test/.com` values.
- **production** (strict only): `/` and `/contact/` must have `form[data-lead-form]` (else sitekey missing at build time); no Cloudflare test sitekey (`1x000...`, `2x...`, `3x...`) anywhere in built HTML.
- `isStrictEnv(env)` = production-ish `SITE_ENV`; `development`/`test` are the only lenient values.

### 1.10 Deploy to Cloudflare
- Cloudflare **Workers with static assets** (not Pages). No Astro adapter needed for static output. Client-owned Cloudflare account, Owner as member (playbook decision).
- `.claude/settings.json` in the template **denies** `wrangler deploy`, `wrangler secret`, `wrangler d1 execute`, `wrangler@` installs, `npm exec wrangler`, force-push, push to main, reading `.env*`/`.dev.vars`/`*.pem`, `cat .env*`, `env`, `printenv`, `rm -rf`. It auto-allows `npm run build/check/test/check:guards/check:types/test:coverage`, `git status/diff --stat/log --oneline`, and "ask" for edits to `.claude/**`, `package.json`, `vitest.config.ts`, `wrangler.jsonc`, `worker/**`, `scripts/**`, `tests/**`. So the AI never deploys; the Owner runs `wrangler deploy`, `wrangler secret put`, `wrangler d1 migrations apply leads --remote`.
- Launch-time items outside the repo: Cloudflare edge rate-limit rule on `/api/lead`, check Cloudflare AI-bot setting vs robots.txt, real Turnstile sitekey at build time (`PUBLIC_TURNSTILE_SITEKEY`), real D1 id, secrets, daily synthetic test with dead-man alert (playbook 14.8), Search Console, GBP UTM link.
- Env var handling: build-time `PUBLIC_TURNSTILE_SITEKEY` in `.env` (never committed; `.env.example` has the test key); runtime secrets only via `wrangler secret put`; AI is forbidden to read `.env`/`.dev.vars`. Missing `.env` in a git worktree caused 47 of 49 initial Playwright failures in one run (form not rendered) - create `.env` from `.env.example` in every new checkout.

## 2. Scaffolding a new client site (exact steps)

The template README says: "clone this repo (do not use 'Use this template'), re-point `origin`, replace `business.yaml` and the sample content, run `npm run sync:config`, then `npm run check:prod` must pass." Expanded:

```bash
# 0. Toolchain (Node 24 LTS; Astro 7 needs >=22.23.4)
export PATH="$HOME/.local/share/node/node-v24.22.1-linux-x64/bin:$PATH"; node -v

# 1. New repo from the template (not GitHub "Use this template"; no shared history)
mkdir clientsite && cd clientsite && git init
cp -a "/mnt/All/Sakib/Website creation/Site1/site-template/." .   # then delete: node_modules dist .astro coverage test-results .env
rm -rf .astro coverage test-results dist node_modules .env
# also copy worker/migrations/ from demos/kiln-and-coil/worker/migrations (template tree shows none) and diff worker/ against the demo for newer fixes (urgent alerts, delivery columns)
git remote add origin <new private repo>      # new identity: repo-local user.email = noreply (no global identity rule)

# 2. Install + env
cp .env.example .env     # PUBLIC_TURNSTILE_SITEKEY = Cloudflare test key for local only
npm install
npx playwright install chromium
npm run check            # baseline: must be green on the untouched sample first

# 3. Replace facts
#   - edit business.yaml (see section 5 for medical); set is_sample: false, status: draft -> approved
#   - delete sample content in src/content/{services,areas,faq,pages}; write one md per confirmed service,
#     one per area WITH proof, FAQ, pages home/about/privacy/terms/accessibility
#   - brand tokens + fonts (npm i @fontsource-variable/<font>; update imports in global.css/theme.css)
#   - favicon (public/favicon.ico; layout links /favicon.svg - provide it)
npm run sync:config      # SITE_ORIGIN / ALLOWED_SERVICES / EMERGENCY_SERVICES into wrangler.jsonc
#   - edit wrangler.jsonc by hand: name, FROM_EMAIL, ALERT_EMAIL_TO, OWNER_ALERT_TO, D1 database_id (after Owner creates it)

# 4. Develop and verify (one change per commit, on a branch, PR to main)
npm run dev                      # or: astro dev --background  (AGENTS.md)
npm run check                    # full gate
npm run check:prod               # launch gate; will fail until every placeholder/sample/test-key is gone
```

Branch discipline in the repo rules: never commit to `main`, one change per commit, open a PR, Owner merges; never deploy; never read `.env`; ask before commands that send data off machine. Guards and tests are "code you can edit but do not weaken"; the Owner reviews every diff under `scripts/` and `tests/`.

Design-lab setup is separate: `cd site-template && npm install && cd .. && node design-lab/setup.mjs` (symlinks each `dir-*/node_modules` to the template's and copies `.env.example` -> `.env`; errors if lockfiles differ). Not needed for a client repo.

**One page at a time (user's workflow) fit:** the guards require >=5 built pages and `/` + `/contact/`, so a single-page build will fail `runGuards` by design. For incremental building either (a) keep all template pages from day 1 as stubs written from the record and iterate page by page, or (b) temporarily lower `MIN_PAGES`/`REQUIRED_PAGES` in `run.ts` in a clearly marked commit (the Owner reviews it; rules say do not weaken guards, so prefer (a)). Also `pairContent` fails the build if a service in the YAML has no `.md`, so add services to the YAML only as their page is ready (set `offered_confirmed: false` otherwise, or omit).

## 3. GBP site kit: gates and pass/fail

Six files, same front matter (`doc_id`, `kit_version 1.0.0`, `status: draft|in-review|approved|locked`, `depends_on`, `feeds`). Global rules: sequential gates (a file is `locked` only when its gate passes; downstream may start early but cannot be approved before upstream is locked); SSOT in file 02 §2 (retyping a phone number is a defect); every requirement testable; traceability page -> GBP category/service -> keyword -> schema -> tracked conversion -> QA test; client owns accounts, agency gets least privilege; no secrets in files; never edit the master, copy per client to `/clients/<slug>/gbp-site-kit/`. Any leftover `{{` placeholder makes a file non-approvable. Priority M/S/C/W; status symbols not started / in progress / pass / fail / N/A (must state why).

**01 Intake and access** (gate: every M item pass; one fail = do not proceed to 02)
G01-1 accountable approver per decision; G01-2 every KPI has baseline/target/date/source; G01-3 primary conversion chosen (call / book / form / visit); G01-4 §4 classification complete (storefront vs SAB vs hybrid, single/multi location, **regulated industry incl. Healthcare** (drives 04 §6 disclosures and 05 §8 form data handling), booking/CRM, languages, call tracking); G01-5 GBP Manager access verified by actually logging in; G01-6 domain + DNS access verified or client-change process agreed; G01-7 GA4 + GSC access (S); G01-8 any third-party-owned asset has an open transfer request; G01-9 no placeholders. Access matrix R01-010..021: owner of record is client; agency = lowest role (GBP Manager not Owner). A `*.business.site` website URL on GBP is broken (shut down 2024).

**02 GBP audit and canonical record** (gate: §2 locked and client-approved; any later fact change = new version + rerun 06 §1 NAP tests)
Fix-before-build blockers: R02-001 verified/not suspended, 002 real-world name (no keyword stuffing), 003 most-specific primary category, 005 address/SAB setting, 007 local phone answered by the business. G02-1..7: verified; name compliant; categories each map to a confirmed revenue service; SSOT filled + client-approved + locked; www-vs-apex canonical host decided; competitive map-pack benchmark (S); NAP mismatches logged (S). GBP limits: <=10 categories, <=20 service areas, 750-char description. Citation audit: fix Name/Address/Phone now, update Website column only after launch. The §2 YAML is the human version of `business.yaml` (same keys: legal_name, display_name, business_model, address with `publish_address`, geo, phone e164/display, email_public, website_canonical, hours, timezone, categories, service_areas, services, gbp maps_url/place_id, same_as, licenses, founded_year...).

**03 Scope, sitemap, keywords** (gate: keyword->URL map approved, no keyword on two URLs, scope frozen)
Deterministic page rules: P1 Home always; P2 Service page only if in SSOT/GBP category + client confirms offered + distinct intent (SERP overlap >= 6 of 10 = one page) + demand OR top-3 revenue; P3 hub off unless >7 services; P4 location page only for real staffed location with own GBP, or SAB with area-specific proof (else doorway-page risk); P5 About, P6 Contact, P10 Privacy/Terms/Accessibility, P11 404 always; P7 Reviews if >=10 real reviews; P8 standalone FAQ if >=8 real questions; P9 blog off. G03-1..7: every page cites a rule ID; zero duplicate primary keywords; every service traces to GBP; location pages have documented unique proof; URLs per §5 (lowercase-hyphen, <=3 levels, one trailing-slash policy, stable forever); out-of-scope list acknowledged; client approved sitemap. Template: title `<Service> in <City>, <ST> | <Brand>` (guard allows <=70 chars), exactly one H1, nav <=6, phone in header on mobile, service pages link >=2 related + contact, FAQ 3-6 real questions, proof block >=1 review/credential. Conversion events: `phone_click`, `form_submit`, `directions_click`.

**04 Content and assets** (gate: all mapped pages approved; every media file has a rights record; legal pages exist)
Content tracker row count must equal keyword map row count (G04-1); statuses brief -> draft -> internal review -> client review -> approved -> locked, max 2 client rounds. Copy standards R04-001..010 (answer in first 100 words; specifics not adjectives; banned-phrase list; no paragraph reuse <10% overlap; NAP never typed into copy (R04-006); one H1; reading level 7-9; CTA top/bottom; expert attribution for expertise topics). ## 4. Lessons and failures from the build logs

Sources: `docs/superpowers/logs/2026-10-26-hvac-demo-build-log.md`, `...-original-value-plan-hostile-review.md`, `2026-10-27-thermostat/REPORT.md`, `plans/2026-10-27-hvac-production-pass.md`, `plans/2026-10-27-home-redesign-house-in-section.md`, `logs/task-11-design-qa/*`, `2026-10-29-overnight/JOURNAL.md` + `MORNING-REPORT.md`, `vault/wiki/project/*paused*`.

### 4.1 Process pattern that worked
Subagent-driven development: one implementer per task + one independent reviewer (spec compliance + quality); Critical/Important go to a fix subagent and are re-reviewed; Minor deferred to a final review. **Almost every task needed 1-2 fix rounds** (Task 6, 7, 8, 9, 10, 14a/b/c all "Needs fixes, then Approved"). Reviewers who fact-checked on the web caught real errors.

### 4.2 Concrete failures (with causes)
- **Dark mode contrast**: dark-mode `primary` was darker than dark bg (1.05:1, text invisible); fixed to #dbe5ee (13.9:1). Dark Footer/CTABand rendered as light panels -> introduced `panel`/`on_panel` tokens. Accent focus ring on `bg-primary` panels was 2.9/1.83:1. Footer call button illegible (Critical P1) -> `onPanel` outline variant plus an e2e test that computes contrast of every visible CallButton label (>=4.5). Lesson: measure contrast per token pair in both modes and assert in a test (`tests/demo/brand.test.ts`).
- **Safety-critical copy errors in content (CRITICAL)**: a boiler page told a reader who smelled fuel to switch things off and call the contractor, contradicting the gas leave-first rule. Also invented license abbreviations, invented job details, wrong rebate program date (Weatherized tier date wrong; corrected after web check), "internal record" wording leaking into visitor copy, unbacked claims ("works best") caught later by the claims guard. Lesson: all content is generated, so every claim needs a record key; safety lines (gas/CO) come first and are checked; **run the guards on the merged build before calling content done** (worktrees could not build, so reviewers missed guard hits).
- **Merge/worktree hazards**: first doc commit accidentally included 4 staged deletions from an implementer (undone with `git reset --soft`); rule since: path-limited `git commit -- <paths>`. Repo inherited a global git email the owner forbids; fixed with repo-local `user.email` (noreply). Worktrees lacked `.env` -> 47/49 Playwright failures (form not rendered without sitekey). A prior parallel attempt had been applied into a worktree in one batch (uncommitted, one type error).
- **Test fragility**: reduced-motion test failed because a fresh browser context never blocked `challenges.cloudflare.com` (fix: `freshPage` helper); hover state on outline call button turned solid and broke "one filled call at a time" (fix: tint instead of invert; an attempt using `bg-primary/10` was rightly rejected by an existing guard test, guard untouched); stale roofing constants in `site.spec` (22 failures) after adapting to HVAC; a plan conflict (mandated copy contained a word its own test banned; controller ruled for the test).

The KIE image API returned 401 (image generation blocked; nothing spent). The auto-permission mode in tutorials conflicts with the owner's "never skip permissions" rule (open decision). ## 5. What must change for a medical client (NY medical practice)

The template is trades-specific in schema, copy, claims lists, and form semantics. HIPAA/health-specific guidance comes from kit files 01 §4, 04 §6, 05 §8 (R05-076), and `playbook/overlays/vertical/medical-wellness.md` (draft; flagged `counsel`; "as of 2026-10-30, counsel review needed"). Treat the following as an engineering to-do list, not legal advice.

### 5.1 `business.yaml` fields to change or add
- `identity.business_model`: `storefront` (a physical office; address `publish: true`, with street/city/region/postal_code and `geo`), maybe `hybrid` if home visits/telehealth. NY medical offices are normally storefront, so NAP includes the street address and the "no address on SAB" guard path is not used.
- `identity.legal_name` / `display_name`: practice name exactly as on GBP (and on NY DOE/board records). `languages` (patients may need Bengali/Spanish etc.; multilingual = separate scope decision per kit 03 §8).
- `gbp.categories.primary`: e.g. "Doctor", "Family practice physician", "Medical clinic", "Dentist", "Internist", "Pediatrician" (whatever GBP says). **Extend `TYPE_BY_CATEGORY` in `src/lib/jsonld.ts`** (only roofing/HVAC/plumber/GC exist). Candidate schema.org types: `Physician` (a MedicalBusiness subtype; `LocalBusiness` + `MedicalBusiness` per schema.org hierarchy), `MedicalClinic`, `Dentist`, `IndividualPhysician`-style content via `Person`/`Physician` on bios; use `medicalSpecialty`, `availableService` (MedicalProcedure/MedicalTherapy) only when the record lists them. Overlay says: `Person` per provider with `hasCredential` only for credentials verified against the board; insurance plans from `overlay.medical-wellness.insurance_plans` with `as_of` date. Keep the rule "no `aggregateRating`/`review`" (guard enforced; self-serving review markup is ineligible).
- `services[]`: treatments/specialties instead of trades. `emergency` flag: for a medical practice this should be false in most cases; **do not offer emergency form/alert semantics** (the Worker's urgent-alert path exists for HVAC); add a visible "In an emergency call 911" line (an overlay-required line; the auto-check for invented claims flagged "911" once, so whitelist it deliberately). `price_publish`: false unless good-faith-estimate/self-pay notice requires publishing (overlay row medical-wellness.7).
- `service_areas[]`: probably fewer; area pages need real local proof or are not built (kit P4). Likely drop the area route entirely and keep a "locations & hours" block.
- `trust.licenses[]`: one entry per provider (type "NY medical license", number, issuer "NYS Education Department Office of the Professions", `registry_url` to the public verification page, expiry). Add `board_certifications`, `npi` and `accepts_insurance[]` plus `insurance_as_of` as NEW schema fields (Zod + tests). The existing `expires`-guard will fail builds on expired licenses (good). `trust.team[]` (providers): `consent` is already required for photos.
- `trust.insurance` / `insurance_certificate_seen` currently model contractor liability insurance; for medical it means accepted *health plans*. Do not reuse the same keys (the claims gate would mislead); add distinct fields.
- `claims.forbidden`/`allowed_if_key_present`: replace roofing list. Add medical-claim bans: "best", "top doctor", "#1", "guaranteed", "cure", "painless", "safe and effective", "no risk", "fastest", "leading" and outcome/comparative claims; "board-certified" allowed only if `trust.board_certifications[]` present; "accepting new patients" allowed only if a record flag says so (`new_patients_accepted`). Health claims on service pages must be reviewed by the provider.
- `conversion.primary_cta`: `call` or an appointment request; add `patient_portal_url` (kept apart from the new-patient path) and a booking-tool block if used. `conversion.answered_by_person` still gates "speak to a person". `conversion.sms_consent_implemented` stays false unless TCPA consent is built.
- `contact.hours` + after-hours text: add an explicit "not for medical emergencies" message; `after_hours` = answering service text.
- `analytics`: GA4 off by default for a medical site, or configured cookieless on non-clinical pages only. The overlay says no ad pixels or session replay on appointment, portal, condition or provider-search pages and counsel approves analytics there. The template already has no tag manager/ad pixel; keep it that way and consider gating `ga4_id` per page.
- `provenance`: keep who-said-what-when for every license/credential (the kit wants provenance).

### 5.2 Form and Worker changes (the big risk area)
- Today's lead form collects name, phone, service, ZIP, email, **free-text message (<=1000 chars)** and stores it in D1, emails it (plain text via a Resend-style provider), and optionally copies it to n8n. Free-text can capture symptoms/PHI. Kit R05-076 (M): no health details collected unless the form vendor signs a BAA. So: (a) remove the free-text `message` field or relabel it "Preferred appointment time or question about scheduling (do not include medical information)" plus a visible notice; (b) remove/keep `ACK_EMAIL=off`; (c) remove the `service` dropdown values that reveal a condition if the service list is condition-based (a service choice + name + phone can be PHI when tied to a treatment); (d) consider making the form a callback request (name, phone, preferred time, new/existing patient) and keep the phone as the primary action; (e) do not route leads through n8n/Resend/Cloudflare logs unless each vendor has a BAA or counsel signs off that the data is not PHI; (f) Cloudflare D1/Worker/Turnstile have no BAA by default - check before storing anything health-related; (g) shorten retention (`scheduled.ts` purge windows) and avoid logging; (h) email alerts should be "new request, open the dashboard" with no content, not the content itself.
- Existing portal/EHR booking: link out to the practice's HIPAA-compliant scheduling/portal vendor (separate path for existing patients).
- Guards to add/adjust: a guard that fails the build if any form field name matches health terms (symptom, condition, diagnosis, medication, dob, ssn, insurance id); a guard that fails if analytics/pixels appear on appointment/portal pages; extend `claims` fixtures for medical bans; extend `nap` guard to also check provider names vs record.

### 5.3 Pages/components to add or drop (against overlay)
Add: Services/treatments (one each), Providers (one bio each with credentials and board-lookup link), Locations & hours, Insurance & pricing (dated list), New patients (forms, what to bring), Patient portal link, Telehealth (if offered), Notice of Privacy Practices, Good-Faith-Estimate notice (self-pay/uninsured, prominent and findable), nondiscrimination/language assistance notice (where applicable), Accessibility statement (practice may be an HHS-funded entity facing WCAG 2.1 AA duty with 2027-2028 dates; counsel). Drop: area pages, before/after galleries (unless written patient consent + counsel), health-claim blogs without clinical review, ReviewsEmbed unless real attributed reviews with permission (and replies must never confirm someone is a patient). Providers map to the existing `PersonCard` and `LicenseBlock` components; add `ProviderCard`, `InsuranceList`, `NewPatientSteps`, an emergency banner and a portal link component, and register them on `/design-system`. UX per overlay: find-provider by specialty/location/language, booking fully usable on phones with a one-tap call, larger default text and plain-language copy for older readers, scheduling-only data collection.

### 5.4 Compliance rows the overlay lists (all `counsel`, source 45 CFR via Cornell LII, grade B, opened 2026-10-30)
Notice of privacy practices must be posted prominently and electronically (45 CFR 164.520); good-faith estimate notice for uninsured/self-pay patients on the website (45 CFR 149.610); FTC Health Breach Notification Rule if health data held outside HIPAA (16 CFR 318.1); HHS-funded entities' web accessibility duty to WCAG 2.1 AA (45 CFR 84.84). NY-specific rows live in `playbook/overlays/jurisdiction/new-york.md` and `nyc.md` (read them; the medical overlay says state board and state health-privacy rows are added via `jurisdictions`). The overlay requires `counsel` in the site record. Also from the vault: plumbers must show license info under NYC Admin Code 28-408.6.2 (not medical, but note that NY has an "advertising must show license number" culture; check NY Education Law/OP rules for physician advertising and title use, which this repo has NOT researched).

### 5.5 Other template adjustments
- Copy rules: remove trades-specific defaults ("Free estimate", emergency, "service call fee"), replace with appointment language; the `offers` block is trades-only (`free_estimate`, `same_day`, `service_call_fee`) - repurpose or drop (fee text must not imply medical pricing without counsel).
- `LicenseBlock`/`TrustBar` copy: "licensed" guard maps to `trust.licenses[].number`; for physicians write "NY State licensed physician, License #..., verify at <registry URL>" gated by the record, never a generic "licensed/insured".
- `_headers` CSP: if embedding a scheduling widget, add only its exact host to `frame-src/script-src`; keep third-party scripts off appointment/portal pages; keep Turnstile only on pages with a form.
- Privacy/terms/accessibility/NPP legal pages: the vault notes `legal-policy-templates` found to be app-oriented and needing heavy adaptation; `footer-and-legal-pages-notes.md` has the competitor/legal audit. Counsel is accountable per kit 04 §6 ("client or their counsel is accountable").
- SEO: title pattern `<Specialty> in <Neighborhood/City> | <Practice>`; YMYL (health) content needs author attribution and clinical review (R04-010); FAQ rich results are limited to authoritative gov/health sites - do not promise them.
- GBP: practice name must match GBP exactly; verify provider listings and citations (Healthgrades, Zocdoc, Vitals) in the kit 02 §5 audit; update the Website column only after launch.
